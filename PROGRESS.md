- [17:44] [M2] DECISION: line direction convention for Zone.direction and cross_line payload.direction: looking from point a to point b in normalised image coordinates, `a_to_b` means the track goes from the left of the line to the right (b_to_a the reverse). Left is where dx*(py-ay) - dy*(px-ax) > 0, with y growing downwards. Why: the contract did not define it. Impact: M4 must draw the inward arrow for `a_to_b` accordingly; M3's enter/exit use a_to_b as inwards.
- [17:44] [M2] DECISION: L2 means attributes + events for now (ReID features join it in P2.14/P2.15). Re-running L2 is idempotent and recomputes events for every stored zone.
- [18:48] [M4] DECISION: frontend is one Next.js (App Router) app: `/` is the scroll story of the system, `/app` the operator product on the light table (PLAN §10). Replaces the Vite assumption in PLAN §8.4. Why: one codebase, shared tokens and contracts types; the story ends by switching the light table on and walking into `/app`. Impact: M1 `make up` serves the built frontend (`npm run build`, static output); UI dev server is `npm run dev` in `frontend/`.
- [19:56] [M2] DECISION: the burned-in clock is only trusted when two frames 5 s apart read times that differ by 5 s +/- 2 s (the video's own timeline), because vision models invent plausible timestamps. Source labels osd and slate. Precision is the whole second shown on screen (about +/- 1 s). Why: a wrong clock silently breaks every time query.
- [21:24] [M2] DECISION: ingest.colour_engine stays `legacy` by default until human labels (scripts/colour_label_tool.py) confirm v2; switch with IngestSettings(colour_engine='v2'). Why: the stand-in labels come from a model that is itself unsure. Evidence so far: skin removal gave no gain (left off); thresholds tuned on half of the stand-in labels made the held-out half worse (0.498 -> 0.471 objective), so no tuned thresholds are adopted; isotonic confidence calibration cut the held-out calibration error from 0.068 to 0.042. Impact: M3's attribute scoring.
- [22:03] [M2] DECISION: ingest.colour_engine default is now `v2` (was legacy). Why: 'no false answers' for submission; v2 agrees better with two independent opinions (local vision model on 195 crops: upper 56% -> 70%, lower 61% -> 75%, vehicles 42% -> 62%; caption colour words 24% -> 45%) and removes phantom colours; it falls back to fixed regions when the segmentation checkpoint is missing. Human labels (scripts/colour_label_tool.py) can still overturn it: set IngestSettings(colour_engine='legacy').
- [22:03] [M2] DECISION: linking is conservative on purpose (see request to M3): a wrong merge produces a false path or an undercount, a missed link only produces a shorter path.
- [22:25] [M2] DECISION (colour, from the owner's human labels, 195 crops, 150 people x upper+lower and 45 vehicles; 44 slots marked unsure and excluded): REAL accuracy on the held-out half, original method -> tuned v2: upper body exact 52% -> 64% (exact-or-adjacent 88% -> 90%), lower body exact 45% -> 63% (87% -> 85%), vehicles exact 36% -> 32% (adjacent 77% -> 82%; only 22 labels, too few to judge). Rare colours stay weak (macro recall about 25%). The thresholds were tuned on the tune half only and are in config/colour_calibration.json (achromatic chroma 22, black L* 16, trousers use their own thresholds because dark denim was being called black: 21 of 31 blue trousers). Calibrated confidence is trustworthy on held-out labels: 0.8-1.0 -> 100% (upper) / 95% (lower) correct, 0.4-0.6 -> about 40% (coin flips); calibration error 0.109 -> 0.031. Therefore a colour is only STORED when its calibrated confidence is >= 0.6 (IngestSettings.colour_min_conf); otherwise upper_color / lower_color / color are left out (unknown) and the attrs JSON carries `colour_unsure` and `*_conf`. Consequence on meva-school: colours known for 45% of people (mostly black) and 8 of 45 vehicles. Why: a guessed colour that is wrong 60% of the time is a false answer; unknown is honest. Impact: M3 must treat a missing colour as 'no information' (not as 'not that colour'); SigLIP similarity still carries colour semantics.
- [22:58] [M2] DECISION: detector input size is automatic (frame width rounded to 32, between 640 and 1280; settings det_imgsz=0, det_imgsz_max=1280). Why: on the MEVA hospital 1080p clip the 640 px detector found 6 cars in 12 frames against 25 at 1280 (70 at conf 0.1) and the index held 1 car track instead of 4. Cost: about 3-4x per frame at 1280, paid only by HD footage. EPFL-size frames stay at 640.
